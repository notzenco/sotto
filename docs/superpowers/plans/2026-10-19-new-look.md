# The New Look Implementation Plan

**Status:** complete. All ten tasks were implemented and reviewed on branch `new-look`, followed by a fix pass after the final whole-branch review. That pass covered take ownership and cancellation, the Notch caret fallback, and meter visibility. The spec's "Decisions made during implementation" lists where the build departed from this plan.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Sotto's text-box slip with a customisable animated listening indicator (Pill, Notch, Dot), and replace the one-page Settings with a sidebar Settings window.

**Architecture:** Everything that doesn't need AppKit goes into `SottoCore` with XCTest coverage: the settings model, level metering, indicator phases and timing, problem copy, bar heights, and placement maths. The app target gets an `IndicatorPanel` (a borderless non-activating `NSPanel` hosting a SwiftUI `IndicatorView`) that replaces `SlipPanel`. It also gets a `SettingsWindowController` hosting a SwiftUI `NavigationSplitView` with one pane per category.

**Tech Stack:** Swift 6, SwiftUI, AppKit, Accessibility (AX) APIs, ServiceManagement (`SMAppService`), XCTest, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-10-19-new-look-design.md`. Mockups: `docs/superpowers/specs/2026-10-19-new-look/listening-indicator.html` and `settings-window.html`.

## Review Focus

These are the inputs most likely to bite a real user, which the spec implies but doesn't spell out. Each one has a pinning test in the task named.

- **An old or odd `settings.json`** (missing new keys, an unknown style string, an out-of-range size) keeps every other setting. It must not reset to defaults. Pinned in Task 1.
- **Apps that report a zero-size or off-screen caret** (Electron apps, some terminals). Treat the caret as unknown and use the chosen position. Pinned in Task 4.
- **Back-to-back takes.** The previous take's "done" or "problem" timer must not hide the next take's indicator. Pinned in Task 3.
- **A very long problem message or live caption** stays clamped to its maximum width and fully on screen. Pinned in Task 4.
- **Silent, NaN or infinite audio buffers** keep the level finite and the bars at their floor. Pinned in Tasks 2 and 5.

### Task 4: Indicator placement maths

**Files:**
- Create: `Core/IndicatorLayout.swift`
- Test: `Tests/IndicatorLayoutTests.swift`

**Interfaces:**
- Consumes `IndicatorStyle`, `IndicatorPosition` and `IndicatorDisplay` from Task 1.
- Produces, `public` in `SottoCore`. All rectangles use AppKit's global coordinates, with the origin at the bottom left.
  - `struct ScreenGeometry: Equatable, Sendable { var frame: CGRect; var visibleFrame: CGRect; var notch: CGRect? }`, with a memberwise `init`.
  - `struct IndicatorPlacement: Equatable, Sendable { var body: CGRect; var caption: CGRect? }`
  - `enum IndicatorLayout` with these constants: `edgeMargin = 16`, `topMargin = 8`, `caretGap = 8`, `captionGap = 6`, `maxBodyWidth = 420`, `maxCaptionWidth = 360` (all `CGFloat`). Its functions are:
    - `static func usableCaret(_ caret: CGRect?, screens: [ScreenGeometry]) -> CGRect?`
    - `static func screenIndex(screens: [ScreenGeometry], display: IndicatorDisplay, position: IndicatorPosition, pointer: CGPoint, caret: CGRect?) -> Int?`
    - `static func place(body: CGSize, caption: CGSize?, style: IndicatorStyle, position: IndicatorPosition, screen: ScreenGeometry, caret: CGRect?) -> IndicatorPlacement`

**Placement rules** (these are the decisions the tests pin):
- **Widths.** Clamp the body to `maxBodyWidth` and the caption to `maxCaptionWidth`.
- **Pill and Dot at the bottom.** Centre the body on `visibleFrame.midX`, with `minY = visibleFrame.minY + edgeMargin`.
- **At the top.** The body's `maxY = visibleFrame.maxY - topMargin`.
- **At the caret.** The body is centred on `caret.midX`, with `maxY = caret.minY - caretGap`. If that would fall below `visibleFrame.minY`, use `minY = caret.maxY + caretGap` instead. A `.caret` position with no usable caret behaves like `.bottom`.
- **Notch.** Ignore the position. Centre on `notch?.midX ?? frame.midX`, with `maxY = frame.maxY`.
- **Captions.**
  - Pill: above the body when it's at the bottom, below the body otherwise (`captionGap` apart, centred).
  - Notch: below the body.
  - Dot: to the right (`minX = body.maxX + captionGap`, vertically centred).
- **Staying clear of the caret.** Only applies when a caret is given.
  - The caret's line is the band `CGRect(x: frame.minX, y: caret.minY - 2, width: frame.width, height: caret.height + 4)`.
  - If the union of the body and caption intersects the band, a Pill or Dot at the bottom or top is re-placed once at the opposite edge.
  - For the Notch, the caption moves to `maxY = band.minY - captionGap`.
- **Finally,** shift each rectangle horizontally so it lies inside `visibleFrame`.
